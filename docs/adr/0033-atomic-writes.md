# ADR 0033：Rocky 自己的檔案整個換掉，不寫一半

- 日期：2026-10-12
- 狀態：已採用（架構審查剩下的「現在做」，第四個 PR）；補充 ADR 0006 和 ADR 0021

## 背景

- **截斷的快照會被寫回去。** 快照（改檔前的版本）直接寫進檔案。磁碟滿了或當機時，檔案只寫了一半；之後還原會把
  這一半寫到使用者的檔案上，而且同樣內容的下一次快照看到檔案已經存在，就沿用這份壞的。
- **截斷的 `secrets.json` 讓 Rocky 起不來。** 模型金鑰和 MCP 權杖存在 `secrets.json`，讀到一半的 JSON 會在每次讀設定
  時丟出錯誤。
- `api-token` 也是直接寫入；它讀到太短時會重新產生，所以影響只是要重新登入。

## 決定

1. Rocky 自己的檔案（快照、`secrets.json`、`api-token`）先寫到旁邊的 `<檔名>.tmp`，寫完並 `fsync` 後才改名蓋過原檔。
   Windows 上改名遇到 EPERM、EACCES、EBUSY（防毒、索引程式暫時占用）時，短暫等待後重試幾次。寫入失敗時刪掉暫存檔，
   原檔不變。
2. 讀快照時檢查內容的 SHA-256 和檔名相符。不符的那個檔案不顯示差異、標成「已損壞」，還原時略過它，同一輪的其他
   檔案照常還原；預覽則說明它已損壞。存同樣內容時，內容不對的舊檔會重寫。
3. 讀不了的 `secrets.json` 改名成 `secrets.json.broken` 留給使用者（已有的舊 `.broken` 被取代），Rocky 照常啟動，
   在紀錄裡說明要重新輸入金鑰。編輯器加上的 BOM 不算壞掉。
4. 暫存檔和 `.broken` 和原檔一樣是私密檔（ADR 0028）：以完整路徑或檔名讀取一律詢問，OpenCode 讀取也詢問。
5. 這個寫法放在 `effects`（`effects/atomic-write.ts`）；`store` 因此可以使用 `effects`（ADR 0021 的分層表）。`effects`
   仍然不依賴 Rocky 的其他部分。

## 限制

- 使用者的專案檔案不在這個範圍：執行器照舊直接寫入。
- `fsync` 只對檔案本身；資料夾的 `fsync` 沒有做，當機時改名本身仍可能遺失（檔案會是舊的或新的，不會是一半）。
- 萬用字元（`secrets.json.*`）不會因為暫存檔和 `.broken` 而詢問；加進去會讓 `rm *.tmp` 這類常見指令也詢問。
- 手動編輯 `secrets.json` 寫錯（例如多一個逗號）也會被移到 `.broken`，只在伺服器紀錄裡說明，設定頁只顯示沒有金鑰。
- 暫存檔名固定。同時啟動兩個 Rocky 寫同一個檔案時，結果是其中一個寫入的內容（和以前一樣）。

## 驗證

Cloud Linux、Node 24.21.0、OpenCode 1.18.34：`npm run check`（286 個測試）、`npm run test:e2e`（30 步）和
`npm run test:e2e:jobs`（10 步）都 exit 0。寫到一半的磁碟錯誤用替換 `node:fs` 的單元測試模擬（不用 ulimit）。每個修正
單獨拿掉後都有測試失敗。Windows 上改名重試沒有測試，也沒在 Windows 上跑。
