# ADR 0030：對話送不出去要說；重新整理後接回進行中的這一輪

- 日期：2026-10-12
- 狀態：已採用（架構審查剩下的「現在做」，第一個 PR）

## 背景

- **對話太長就默默卡住。** 每一輪，瀏覽器都把整段對話送給伺服器（CopilotKit 的 `RunAgentInput.messages`）。所有 `/api`
  路由共用 2 MB 上限，大約讀 11 份長中文文件就超過。超過時伺服器回 413，`copilotkit.runAgent` 不會拋錯，畫面上
  Roko 顯示「完成」，沒有回覆也沒有錯誤，剛打的字也不見了；之後每一輪都一樣。模型那邊有 Deep Agents 的摘要，
  不會先撐爆。
- **重新整理後，這一輪的下一個問題收不到。** 伺服器在瀏覽器離開後仍繼續跑這一輪，重新連上時會送出歷史紀錄和
  進行中這一輪的事件。但歷史裡有舊的狀態快照（模式、規劃模式、等待中的問題），所以頁面只接受「自己送出的那一輪」
  的快照。重新整理或切換對話後，新的問題全被丟掉，這一輪就停在關卡上等，畫面上沒有任何提示。
- **過期的問題卡住輸入框。** 回答一個已經不在的問題（另一個分頁答過、伺服器重啟），伺服器回 409，畫面顯示
  「沒送出：not-pending」，問題面板一直蓋住輸入框。
- **兩份核准模式。** 輸入框旁改了模式，設定頁仍顯示舊的值；「放手」模式下危險指令不問，所以這個值很重要。
- **當機中斷的那一輪，改動找不到。** 這一輪的紀錄和快照逐筆寫入，對話內容卻在結束時才存。當機後找不到要掛
  還原卡片的訊息，卡片就不顯示。

## 決定

1. 對話這一輪的路由（`/api/copilotkit` 和底下的路徑）上限 32 MB，其他 `/api` 路由維持 2 MB。先檢查 token 再看
   大小，沒有 token 的請求不會讓 Rocky 讀進任何內容。根本的做法是由伺服器保存對話、
   瀏覽器只送新訊息，但那會改變模型輸入、工作量大，等 32 MB 不夠再說。
2. 這一輪失敗時，頁面說明原因，Roko 不顯示「完成」。伺服器還沒開始這一輪（413、離線、被拒）時，把那則訊息拿回來
   放回輸入框（輸入框已有新打的字就接在前面）；已經開始後才斷掉，訊息留在對話裡，因為伺服器可能已經做了事。
   413 有自己的訊息：「這段對話太長，無法再送出。請開一個新對話繼續。」
3. 伺服器重播歷史時略過狀態快照（`STATE_SNAPSHOT`、`STATE_DELTA`）；頁面需要的目前狀態，由它自己讀
   （`/threads/:id/approvals`）。於是頁面收到的快照都來自進行中的這一輪，不必再只認自己送出的那一輪；重新連上後
   也收得到新的問題。連線結束（這一輪跑完）時，頁面重新讀一次紀錄。進行中這一輪的快照裡，頁面只取等待中的問題和
   規劃模式；規劃模式從介面改了，關卡會發出新快照，接回的頁面不會拿到舊值。
4. 回答時收到 409，就重新讀目前等待中的問題，不顯示錯誤代碼。
5. 核准模式只有 App 一份：輸入框旁改了，用伺服器回傳的設定更新它；快照裡的模式不再採用。
6. 有改動但找不到對話內容的那一輪，還原卡片放在對話最後。
7. 伺服器錯誤的紀錄加上方法、路徑和堆疊。

## 限制

- 找不到對話內容的那一輪，卡片放在最後，不一定在它原本的位置；這一輪進行中時先不顯示，避免和新的卡片混在一起。
- 重新整理後接回的這一輪，沒有「停止」按鈕和思考中的提示；問題和回覆照常出現，這一輪結束後輸入框恢復。

## 驗證

Cloud Linux、Node 24.21.0、Playwright 的 Chromium、OpenCode 1.18.34：`npm run check`（284 個測試，含真的 OpenCode
的整合測試）、`npm run test:e2e`（35 步）和 `npm run test:e2e:jobs`（10 步）都 exit 0。e2e 用攔截的請求重現 413 和送出後才斷掉的串流，也重新整理進行中的一輪、回答已過期的問題。每個修正單獨
拿掉後都有測試失敗；規劃模式路由改走關卡這一行沒有單元測試，由關卡本身的測試涵蓋。沒在 Windows 上跑。
