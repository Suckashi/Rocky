# ADR 0028：政策兌現 ADR 0019 的承諾

- 日期：2026-10-11
- 狀態：已採用（架構審查的第三項，第一部分）

## 背景

ADR 0019 承諾：讀機密檔在兩種模式都會問；「需要時才問」模式下，危險指令和專案外的動作會問。架構審查找到幾個沒做到的地方：

- 政策只看指令碰到的第一個規則。`cat /etc/hosts .env` 先碰到「專案外」，`sh -c "rm -rf dist && cat .env"` 先碰到「危險」，
  結果在「放手」模式下讀 `.env` 不會問；「這個對話都允許」也記成錯的類別，而且用第一個程式命名。
- 強制推送只認 `--force`、`-f` 這兩個完全相同的字，`git push -uf`、`--force-with-lease=main` 會當成一般推送。
- `sh -c` 字串裡的 `~`、`$HOME`、`%USERPROFILE%` 由 shell 展開，Rocky 卻當成專案裡的路徑，所以改家目錄的檔案不會問。
- `$(...)` 或反引號讓整串 shell 指令變成「無法解析」，只看外層的 `sh`，禁止規則和危險判斷都失效。
- Rocky 自己存模型金鑰和 MCP token 的 `secrets.json`、API token 檔，不在機密檔清單上。
- 一般的 `git push` 不問：把東西送出電腦、收不回來，卻和 `git status` 一樣直接放行。

## 決定

1. 動作碰到的所有規則都要過關，不是只看最嚴重的一個。「放手」模式放行讀機密檔以外的規則；「這個對話都允許」只放行它自己那一類；
   「一律允許」規則涵蓋指令裡每個程式時，放行讀機密檔以外的規則。還沒過關的規則裡取最嚴重的來問：
   讀機密檔 > 寫機密檔 > 受保護的檔案 > 危險指令 > 專案外。類別以真正碰到規則的那個程式命名。
   所以允許了「遞迴刪除」，同一串指令裡的強制推送照樣要問；一串指令有幾種危險就記幾種。
2. 強制推送：`push` 子指令自己的參數裡，任何含 `f` 的短旗標（`-f`、`-uf`、`-fu`）、任何 `--force…`、`+ref`。
   子指令是 git 自己的選項（`-C 目錄`、`-c 設定` 等）之後的第一個字，所以 `git stash push`、`git commit -m push` 不算推送。
   `git checkout -qf` 同理。
3. 從 shell 字串拆出來的指令記下是哪種 shell。字首被 shell 換掉的字，位置未知，當成專案外：POSIX 和 PowerShell 是 `~`、`$變數`、
   `${變數}`（PowerShell 還有 `$env:變數`），`%變數%` 只有 cmd 才算。字中間的 `$`、`%` 照字面判斷（`sed 's/foo$/bar/'`、
   `printf '%s/%s'`），這是取捨：`src/$X` 這種寫法看不出 `$X` 指到哪裡。
   換掉的部分之後若是機密檔（`~/.ssh/id_rsa`、`$HOME/.aws/credentials`）或 Rocky 自己的機密檔名，照樣算讀機密檔，「放手」也會問。
   處理檔案的程式（`cp`、`mv`、`rm`、`cd`、`copy` 等）連單獨的 `$HOME`、`~`、`$(...)` 也算目標。
   直接以 argv 執行的程式不受影響（`ls ~/x` 的 `~` 就是一個叫 `~` 的資料夾）。
   PowerShell 的跳脫字元是反引號，反斜線是路徑分隔字元：拆字時保留，`C:\Users\u\.ssh\id_rsa` 才認得出是機密檔。
4. `$(...)` 和反引號：拆出來，外層指令和每個內層指令都判斷；外層用 `$SUBSTITUTED` 代替（字首是 `$`，所以算 shell 換掉的字）。
   單引號裡的不展開；括號或反引號不成對時仍當成無法解析。
5. Rocky 資料夾裡的 `secrets.json` 和 `api-token` 是機密檔，不論專案設在哪裡；比對前先解開連結，資料夾經由連結指過去也認得。
   Rocky 自己的 `grep` 也略過這兩個檔；OpenCode 的讀檔規則也加上這兩個名字。
6. 所有 `git push` 都算危險指令（`push`）：「需要時才問」會問，「放手」照樣放行；「這個對話都允許」可以放行同一類。

都是讓既有的承諾成真；一般在專案裡工作（`npm test`、`git status`、`git commit`、編輯檔案）不會多出詢問。
