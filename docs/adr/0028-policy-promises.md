# ADR 0028：政策兌現 ADR 0019 的承諾

- 日期：2026-10-11
- 狀態：已採用（架構審查的第三項，第一部分）

## 背景

ADR 0019 承諾：讀機密檔在兩種模式都會問；「需要時才問」模式下，危險指令和專案外的動作會問。架構審查找到幾個沒做到的地方：

- 政策只看指令碰到的第一個規則。`cat /etc/hosts .env` 先碰到「專案外」，`sh -c "rm -rf dist && cat .env"` 先碰到「危險」，
  結果在「放手」模式下讀 `.env` 不會問；「這個對話都允許」也記成錯的類別，而且用第一個程式命名。
- 強制推送只認 `--force`、`-f` 這兩個完全相同的字，`git push -uf`、`--force-with-lease=main` 會當成一般推送。
- `sh -c` 字串裡的 `~`、`$HOME`、`%USERPROFILE%` 由 shell 展開，Rocky 卻當成專案裡的路徑，所以改家目錄的檔案不會問。
- `$(...)` 或反引號讓整串 shell 指令變成「無法解析」，只看外層的 `sh`，禁止規則和危險判斷都失效。
- Rocky 自己存模型金鑰和 MCP token 的 `secrets.json`、API token 檔，不在機密檔清單上。
- 一般的 `git push` 不問：把東西送出電腦、收不回來，卻和 `git status` 一樣直接放行。

## 決定

1. **所有規則都要過關。** 動作碰到的每條規則各自要過關，不是只看最嚴重的一條。
   - 「放手」模式放行讀機密檔以外的規則。
   - 「這個對話都允許」只放行它自己那一類；允許強制推送也放行一般推送。
   - 「一律允許」規則涵蓋指令裡每個程式時，放行讀機密檔以外的規則。沒有 `*` 的規則也可以直接對上整個指令：
     「一律允許」對 `sh -c …` 存的就是整串，以前存了也不會生效。
   - 還沒過關的規則裡取最嚴重的來問：讀機密檔 > 寫機密檔 > 受保護的檔案 > 危險指令 > 專案外。類別以真正碰到規則的
     那個程式命名，「在專案外的資料夾執行」也按每個程式各記一條。
   - 一串指令有幾種危險就記幾種，所以允許了「遞迴刪除」，同一串裡的強制推送照樣要問。
   - 按下「這個對話都允許」時，同一對話裡正在等的同類問題會重新判斷：都過關才一起放行；還卡在別的規則的，
     改成問那條規則。
   - 一個路徑同時是機密檔（或受保護的檔案）又在專案外，兩條都要過關。
2. **強制推送。** 看 `push` 子指令自己的參數：任何含 `f` 的短旗標（`-f`、`-uf`、`-fu`）、任何 `--force…`、`+ref`。
   - 子指令是 git 自己的選項（`-C 目錄`、`-c 設定` 等）之後的第一個字，所以 `git stash push`、`git commit -m push`
     不算推送。
   - `git checkout -qf` 同理。
3. **照 shell 的方式讀指令字串。** `sh -c`、`cmd /c`、`powershell -Command` 的字串由同一個拆字器處理。
   - 引號：單引號、雙引號、反斜線。
   - 分隔：`;`、`&`、`&&`、`|`、`||`、換行、括號。`#` 之後是註解。
   - `if`、`then`、`do`、`{` 這類保留字不是程式。
   - 開頭的 `X=1` 是設變數，不是程式；值當成可能的路徑來看。
   - 轉向：`> f` 是寫入，`< f` 是讀取。`2>&1`、heredoc、here-string 不是檔案。heredoc 的內容不是指令；
     分隔字沒加引號時，內容裡的 `$(...)` 照樣判斷。
   - `$(...)`、反引號、`<(...)`：拆出來，裡外的指令都判斷，外層用 `$SUBSTITUTED` 代替。
   - 拆不開或包太多層的部分當成「看不懂的程式碼」，用裡面的字來判斷；同一串裡其他指令照樣判斷。
     `node -e` 這類內嵌程式碼也是這樣。
   - `sh -c '…' x y` 後面的 `x y` 是字面上的字，也要判斷。
   - 直接以 argv 執行（不經 shell）時，每個字都是參數：`>`、`<` 只是字，`~/x` 是一個叫 `~` 的資料夾。
   - PowerShell 的跳脫字元是反引號，反斜線是路徑分隔字元：拆字時保留，`C:\Users\u\.ssh\id_rsa` 才認得出是機密檔。
4. **shell 換掉的字。** 字首被 shell 換掉的字，位置未知，當成專案外。
   - POSIX 和 PowerShell 是沒加引號或在雙引號裡的 `~`、`$變數`、`${變數}`（PowerShell 還有 `$env:變數`）。
     cmd 是 `%變數%`。
   - 單引號裡的字、字中間的 `$` 照字面判斷，所以 `awk '$1 ~ /x/'`、`sed 's/foo$/bar/'` 不會問。
   - `$PWD` 換成目前的資料夾。
   - 換掉的部分之後，若是機密檔或受保護的檔案（`~/.ssh/id_rsa`、`$HOME/x/.git/hooks/…`），照樣算。
   - 單獨一個 `~` 對所有程式都是目標。單獨的 `$變數` 只有處理檔案的程式（`cp`、`rm`、`ls`、`grep`、`cd` 等）才算目標。
   - `cd` 不加參數會回家目錄，算專案外。
5. **到處都找機密檔。** 不只找看起來像路徑的字。每個參數、旗標的 `=值`、`@檔案`、變數的值都會檢查；
   `.env*` 這類萬用字元也會。
   - 在機密資料夾（如 `~/.ssh`）裡執行指令，算讀機密檔。
   - `/dev/null`、`NUL` 不是檔案。網址不是路徑。
6. **Rocky 自己的機密檔。** Rocky 資料夾裡的 `secrets.json` 和 `api-token` 是機密檔，不論專案設在哪裡。
   - 比對前先解開連結，資料夾經由連結指過去也認得。
   - Rocky 自己的 `grep` 也略過這兩個檔；OpenCode 的讀檔規則也加上這兩個名字。
7. **所有 `git push` 都算危險指令（`push`）。** 「需要時才問」會問，「放手」照樣放行；「這個對話都允許」可以放行同一類。

都是讓既有的承諾成真。一般在專案裡工作（`npm test`、`git status`、`git commit`、`sed`、`awk`、編輯檔案）不會多出詢問。
另外也少了兩種以前會誤問的情況：`> /dev/null`，以及 heredoc 內容裡的網址路徑。

**限制**

- Rocky 判斷的是指令裡的字，不是程式執行時做的事。腳本檔（`node build.js`）、程式自己組出來的路徑都看不到。
- 在別處設好的變數（`cat $p`）只知道「位置未知」，不知道是不是機密檔。
- `cd "$(git rev-parse --show-toplevel)"` 的目的地未知，「需要時才問」會問。
- 一串指令碰到多條規則時，「這個對話都允許」一次只記一類，可能要按幾次。
