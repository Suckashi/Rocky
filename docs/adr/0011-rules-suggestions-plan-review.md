# ADR 0011：永久規則、Roko 的規則建議、方案審查

- 日期：2026-10-06
- 狀態：已採用
- 程式：`src/server/http/routes/rules.ts`、`src/server/effects/{suggestions,gate,policy}.ts`、`src/server/agent/plan.ts`、
  `src/web/components/{RuleList,RuleSuggestion,PlanPanel}.tsx`
- 測試：`tests/unit/{rules,suggestions}.test.ts`、`tests/integration/agent-tools.test.ts`、`scripts/e2e.ts`、評測 `plan-before-refactor`

## 決定

1. **永久規則在設定頁新增與移除**（approvals.md）。規則是一個指令的開頭，最後的 `*` 代表任意參數；只管指令。
   一條規則只能有一個指令，`*` 只能放最後，「允許所有指令」（只有 `*`）和重複的規則都不能新增。
   政策先檢查危險指令與對外動作，所以允許規則永遠放行不了它們（有測試）。
2. **Roko 的規則建議。** 30 天內，同一類指令因為模式被問、而且被你核准 2 次以上時，建議一條允許規則：
   程式加上子指令的字（最多 3 個）再加 `*`，例如 `npm run lint *`；只剩程式名稱（`node *`）太寬，不建議。
   危險、碰到專案外路徑、串接多個指令、已經被規則涵蓋、你按過「不用了」的，都不會建議。
   建議只是提議：按「設為永久規則」才新增，而且伺服器只接受目前正在建議的那一條。
3. **方案審查。** 新工具 `propose_plan`：較大或做法不只一種的任務，模型先提出 1～3 個方案（標題、說明、步驟、指令）。
   方案是一種新的效果，**任何模式都會問**。核准面板改成方案卡片：數字鍵選方案，下一個數字鍵要求修改（輸入意見），`Esc` 拒絕。
   - 選定後，該方案列出的指令記成「這個對話已核准」，只限參數完全相同、在專案根目錄執行；其他動作照常判斷，
     危險指令與對外動作仍然會問（政策先檢查）。操作紀錄寫下選了哪個方案。
   - 要求修改：意見回到模型，請它修改後再提一次，不能先動手。拒絕：請模型停下來問你。
   - 模型常把指令寫成字串，Rocky 會把單一、能解析的指令拆成參數陣列；含 `&&`、`|` 等的會被略過，不會被預先核准。
   - 提示詞只要求在較大或模糊的任務時提方案；小而明確的任務直接做（評測確認沒有讓小任務多問）。

## 還沒驗證的（限制）

- 規則建議的門檻（2 次、30 天）是先訂的，沒有真實使用資料。
- 方案審查只在單一對話裡生效；預先核准不會帶到別的對話。
- Windows 上的實際操作同樣待擁有者確認。
