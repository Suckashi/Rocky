# ADR 0027：工具失敗只在關卡中介層處理一次

- 日期：2026-10-11
- 狀態：已採用（架構審查的第二項）

## 背景

LangChain v1 只要裝了 `wrapToolCall` 中介層（Rocky 一定有），工具拋出的錯誤就被當成致命錯誤：整輪對話以
`RUN_ERROR` 結束，模型看不到錯誤，也沒機會換個做法。讀到加密的 PDF、損壞的 docx、MCP 伺服器斷線、Windows 上
檔案被 Word 鎖住（EBUSY）都會這樣。

另外，寫入或指令在關卡放行後就發出通行證、寫下「執行中」的紀錄；只有執行器會用掉通行證並結束紀錄。
工具在走到執行器之前就停下（參數不合工具自己的格式、要替換的文字已經不在），通行證一直留著，紀錄停在「執行中」，
重啟後變成「結果不明」，還提供「確認成功」的按鈕，雖然根本沒執行。

## 決定

在 `gate-middleware.ts` 的 `gated()` 外面包一層，成為處理工具失敗的唯一地方：

1. 工具拋出錯誤時，回給模型一個錯誤結果（`Error: <工具> failed: …`），這一輪繼續。照樣往外拋的只有：「停止」
   （run 的 signal 已中止）、LangGraph 自己的流程控制（`isGraphBubbleUp`：interrupt、parent command），以及研究子代理
   （`task`）裡模型服務商的失敗（HTTP 錯誤或連線中斷）：它不是工具的錯，和 Rocky 自己遇到時一樣結束這一輪，
   評測照樣記成服務商錯誤（ADR 0026）。
2. 寫入與指令：工具結束後通行證若還沒用掉，代表沒走到執行器：收回通行證（`PassBook.discard`），紀錄標成
   「沒有執行」（`the tool did not run`）。執行器自己拋錯時照舊記成「結果不明」。
3. 工具自己的判斷先跑（它的錯誤訊息最清楚，例如規劃工具會說「給 1 到 3 個方案」）；判斷通過後、問使用者之前，
   用工具自己的 Zod 格式檢查參數。工具一定會拒絕的參數，不會先問使用者、也不會留下紀錄。MCP 工具的格式是
   JSON Schema，不在這裡檢查。

## 驗證

| 平台                                            | 指令                                  | 結果                                          |
| ----------------------------------------------- | ------------------------------------- | --------------------------------------------- |
| 雲端 Linux，Node 24.21.0                        | `npm run check`                       | 通過，184 個測試，exit 0                      |
| 同上，Command Code `deepseek/deepseek-v4-flash` | `npm run eval -- --repeat 3`（32 題） | 96/96，沒有服務商錯誤，沒有題目退步（exit 0） |

- 新的單元測試各自對應一項修正：沒執行的工具留下「沒執行」的紀錄而不是「執行中」、拋出的錯誤變成模型看得到的錯誤結果、
  執行器已記下「結果不明」的保留原樣、`null` 的拒絕、子代理的服務商錯誤照樣往上丟、停止和中斷照樣往上丟、參數格式檢查。
- 新的整合測試：壞掉的 `.docx` 讓工具出錯，整輪不再以 `RUN_ERROR` 結束；`timeout_seconds: 900` 回傳參數錯誤，不留紀錄。
- 評測裡沒有會讓工具出錯的題目，所以 96/96 只說明沒有退步；錯誤處理本身由上面的測試驗證。
- 沒有在 Windows 上跑過；CI 會在 Windows 跑 `npm run check`。
