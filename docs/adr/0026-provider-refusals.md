# ADR 0026：服務商無故拒絕時重試一次；評測分開記服務商錯誤

- 日期：2026-10-09
- 狀態：已採用

## 背景

ADR 0019 起的四輪評測裡，Command Code（`deepseek/deepseek-v4-flash`）回了 5 次 400 `invalid_request_error`，
錯誤只有一個追蹤碼，沒說哪裡不對。為了查原因，在 Rocky 與服務商之間放一個轉發器跑完整評測：約 400 個請求裡抓到 2 次
（約 0.5%）。把這 2 個請求原封不動重送 26 次（非串流 6 次、串流 20 次）全部成功；把 `read_file` 的內容區塊改成純文字也一樣成功。
所以不是 Rocky 送出固定錯誤的格式，而是服務商偶發的拒絕。

## 決定

1. Rocky 與研究子代理都加上 LangChain 的 `modelRetryMiddleware`（`src/server/agent/provider-retry.ts`）：
   回 400、而且錯誤沒有 `code` 或 `param`（沒說原因）時，等 1 秒重送一次。有說原因的 400（例如上下文太長）不重試；
   第二次還是被拒，這一輪照舊以錯誤結束。模型呼叫不會改變任何東西，重送是安全的；真正格式錯誤的請求最多多花一次呼叫。
2. 評測把「服務商讓這一輪失敗」（HTTP 4xx／5xx 開頭的錯誤、連線中斷）標成 `PROVIDER ERROR`：列出來，但不算分，
   也不進逐題比較。分數只反映 Rocky 有沒有把事情做對。

## 驗證

| 平台                                            | 指令                                  | 結果                                          |
| ----------------------------------------------- | ------------------------------------- | --------------------------------------------- |
| 雲端 Linux，Node 24.21.0                        | `npm run check`                       | 通過，171 個測試，exit 0                      |
| 同上，Command Code `deepseek/deepseek-v4-flash` | `npm run eval -- --repeat 3`（32 題） | 96/96，沒有服務商錯誤，沒有題目退步（exit 0） |

- 新的整合測試：服務商無故拒絕一次後重試成功；有說原因的拒絕不重試；連續兩次無故拒絕以錯誤結束。拿掉重試時這兩個測試都失敗。
- 評測看不到某一輪有沒有重試過，所以這次 96/96 不能證明重試在真實服務商上生效過，只能說沒有退步；重試本身由整合測試驗證。
- 沒有在 Windows 上跑過。
