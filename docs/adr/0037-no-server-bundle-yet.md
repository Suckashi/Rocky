# ADR 0037：暫不把伺服器打包成單一檔案

- 日期：2026-10-12
- 狀態：暫不採用；補充 ADR 0036

## 背景

有些 CLI 用 npm 安裝只要幾秒，例如 `@moonshot-ai/kimi-code` 只有 2 個依賴，其他程式碼都打包在 `dist/` 裡。
Rocky 的正式依賴有 589 個（ADR 0036 決定 8 之後）。這次評估如果也把伺服器打包，能省多少、要付出什麼。

## 評估了什麼（雲端 Linux，Node 24.21.0，npm 11.19.0，esbuild 0.25.10；都在暫存資料夾，沒有改 repo）

用 esbuild 打包編譯好的 `dist/server/start.js`（`--platform=node --format=esm --splitting`）。有兩個套件必須留在外面：
`@napi-rs/canvas` 是原生模組；`pdfjs-dist` 在執行時要讀自己的 CMap 檔。

| 項目                                                | 現在   | 只把網頁依賴移到 dev（已採用，ADR 0036） | 打包伺服器                         |
| --------------------------------------------------- | ------ | ---------------------------------------- | ---------------------------------- |
| 要安裝的套件                                        | 1006   | 605                                      | 3                                  |
| `node_modules`                                      | 991 MB | 567 MB                                   | 70 MB，加上打包檔 19 MB            |
| 安裝時間（清空快取）                                | 44 秒  | 45 秒                                    | 2 秒                               |
| `npm run test:e2e`（35 項，Playwright 的 Chromium） | ✅     | ✅                                       | ✅                                 |
| 單元與整合測試，連同依賴一起打包後執行              | —      | —                                        | 325 通過、5 略過；2 個失敗（見下） |

失敗的 2 個在 `atomic-write.test`：測試用 `vi.mock('node:fs')` 模擬寫入中斷，打包後 mock 沒有作用。這是測試
方式的限制，不是依賴壞掉。

## 為什麼現在不做

- Rocky 是一個人在自己電腦上用（`AGENTS.md`），安裝一次多等 40 秒的影響很小；打包的好處主要給很多陌生人安裝的情況。
- 依賴每個里程碑都在變。打包後每次加依賴都要重新確認它能不能打包、授權有沒有補齊。
- 錯誤堆疊會指向打包後的檔案，要靠 sourcemap 才好除錯。

## 要做的時候要處理的

1. **授權。** 打包進去的第三方套件有 272 個（MIT 209、Apache-2.0 25、ISC 20、BSD 10、其他 8），都要求保留授權聲明。
   要在打包時從 metafile 產生授權檔；其中 16 個沒有 LICENSE 檔、1 個沒有標示授權，要個別處理。
2. **pino** 用 `__dirname` 找 worker 檔（`thread-stream`、`pino/lib/transport.js`）。用到 pino transport 時會找不到檔案。
   這次的流程沒有用到。
3. **unpdf** 內建的 pdfjs 用 `import.meta.url` 載入解碼器，可能影響含 JPEG2000 圖片的 PDF。文字抽取的測試通過。
4. 打包工具：esbuild 或 Vite 8 自帶的 rolldown，要決定用哪個。
5. Windows 沒有驗證，原生模組留在外面的做法要在 Windows 上跑過。

## 什麼時候重新考慮

- 要讓其他人安裝，或公開發佈到 npm；
- 依賴清單幾個里程碑都沒有大變動；
- 安裝時間或大小成為實際的問題。
