# ADR 0031：工作記得自己的儲存庫

- 日期：2026-10-12
- 狀態：已採用（架構審查剩下的「現在做」，第二個 PR）

## 背景

派工（ADR 0008、0012）時，worktree 是整個儲存庫的副本，裡面的路徑相對於儲存庫的最上層。但工作沒有記下它來自哪個
儲存庫：套用和捨棄都用「目前的專案資料夾」。

- 專案是儲存庫裡的子資料夾時（例如 monorepo 的一個 package），套用把 `sub/b.txt` 寫到 `專案/sub/b.txt`，也就是
  `儲存庫/sub/sub/b.txt`，接著刪掉 worktree，工作成果只剩存下來的 diff 文字。在同一個儲存庫的資料夾之間切換專案也一樣。
- 換到別的專案後按「捨棄」，工作標成「已捨棄」，worktree 和分支卻留在原本的儲存庫；畫面上也沒有再試一次的按鈕。
  移除失敗（worktree 被鎖住、Windows 上有檔案正在使用中）同樣被忽略。
- 套用畫面的「工作開始後這個檔案被改過」是用位元組比對。Git for Windows 預設 `core.autocrlf=true`，檔案在磁碟上是
  CRLF、在儲存庫裡是 LF，所以工作改到或刪掉的每個舊檔案都顯示這個警告，警告就沒有意義了。
- 對話在規劃模式時，政策擋下所有寫入，連使用者自己按的「套用」「還原」也被擋。
- 套用逐檔寫入：後面的檔案內容變了，前面的檔案已經寫進去。

## 決定

1. 工作記下 worktree 來自的儲存庫最上層（`jobs.repo`，解開連結後的路徑）。worktree 從那裡建立，套用時路徑接在那裡。
2. 套用只在目前的專案屬於同一個儲存庫時進行，否則照舊回答「專案換過了」。捨棄一律在工作自己的儲存庫進行，
   不管目前開的是哪個專案。這個欄位加入之前的舊工作，照舊用目前的專案判斷。
3. 移除 worktree 時，已經不在的不算錯；還留著的（鎖住、檔案使用中）回報錯誤，工作不標成「已捨棄」，可以再捨棄一次。
   套用完成後才移除失敗的，只在時間軸記一筆，套用照樣算成功。
4. 「被改過」用 Git 的眼光判斷：比較 `git hash-object`（經過專案自己的換行設定和過濾器）和基準提交的內容，跟
   `git status` 一樣。Git 判斷不了時當成改過。
5. 使用者自己按的套用和還原不受規劃模式限制；規劃模式限制的是模型。
6. 套用前先確認每個檔案都還是使用者看到的內容，有一個變了就一個都不寫。寫到一半失敗時，回報已經寫入的檔案，
   再套用一次會寫入同樣的內容。
