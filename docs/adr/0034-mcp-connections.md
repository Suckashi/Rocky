# ADR 0034：MCP 伺服器失敗時，不拖累每一輪

- 日期：2026-10-12
- 狀態：已採用（架構審查剩下的「現在做」，第五個 PR）；補充 ADR 0009

## 背景

- **兩個工具可能同名。** 工具名稱把伺服器名和工具名的其他字元換成 `_`，再截到 64 個字。`a.b` 和 `a_b` 兩個伺服器
  的同名工具因此同名，後登記的那個沿用前一個的判斷（規則和核准）。
- **失敗的伺服器留在背景。** 連上後列工具失敗（逾時）時，已經啟動的伺服器行程沒有被結束。
- **每一輪都重新啟動壞掉的伺服器。** 每一輪開始時都重新連線；失敗的伺服器每輪都啟動一次，等到 20 秒逾時。停止
  這一輪也不會少等。
- **錯誤沒有原因。** 伺服器的 stderr 被丟掉，設定頁只看到「Connection closed」。

## 決定

1. 工具名稱：原本的 `mcp__伺服器__工具` 能唯一讀回時照舊；否則（其他字元、伺服器名含 `__` 或以 `_` 結尾、太長、
   工具名看起來像雜湊結尾）加上真實名稱的短雜湊。工具登記處拒絕同一個名稱登記兩次；伺服器把同一個工具列兩次時，
   只登記一次，這一輪照常進行。
2. 連線失敗時，關閉這次啟動的連線和行程。
3. 錯誤附上伺服器 stderr 的最後 2000 個字。設定裡的值（env、headers、網址查詢參數）在截斷前換成 `***`：整個值、
   JSON 跳脫後的值，以及 `Bearer` 這類前綴後面的權杖；較長的值先換。
4. 失敗的伺服器一分鐘內不再自動重試，直接回報上次的錯誤；打開設定頁會立刻重試；改了設定也會。
5. 這一輪被停止時不再等連線；連線本身繼續，成功了下一輪就能用，失敗了也照樣記下。關閉 Rocky 時，等還在啟動的
   伺服器再一起關掉。

## 限制

- 伺服器修好後，最多等一分鐘（或打開設定頁）才會再連上。
- Windows 上用 stdio（例如透過 npx）的伺服器仍沒有實測（ADR 0009）；SDK 只結束直接啟動的行程，透過 `cmd.exe` 或
  npx 啟動的伺服器本身可能留下。
- 少於 4 個字的值、命令列參數裡的權杖，以及伺服器把權杖改寫後再印出的內容，不會被遮住。

## 驗證

Cloud Linux、Node 24.21.0：`npm run check`（291 個測試，含真的 OpenCode 的整合測試）和 `npm run test:e2e`（30 步，含
MCP 那一步）都 exit 0。新測試用會當掉、會卡在列工具的測試伺服器。每個修正單獨拿掉後都有測試失敗。沒在 Windows 上跑。
