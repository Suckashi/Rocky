# ADR 0012：工作在背景排隊

- 日期：2026-10-06
- 狀態：已採用（取代 ADR 0008 決定 7「工作跟著對話這一輪走」）
- 程式：`src/server/jobs/{runner,store}.ts`、`src/server/agent/delegate.ts`、`src/server/http/routes/jobs.ts`、
  `src/server/store/db.ts`（migration 4）、`src/web/pages/JobsPage.tsx`、`src/web/App.tsx`
- 測試：`tests/integration/jobs.test.ts`、`scripts/e2e-jobs.ts`、評測 `delegate-to-opencode`

## 決定

1. **派工後立刻回到對話。** `delegate_to_opencode` 只把工作排進佇列就回覆「已排入背景」，這一輪結束，你可以繼續聊別的。
   工具回覆要求模型不要等、不要宣稱結果、不要承諾稍後自己回報。
2. **一次跑一個。** OpenCode 一次只跑一個工作，其他的「排隊中」，依序執行；工作頁顯示排第幾個。
3. **工作在自己的執行緒裡問。** 工作執行時的核准、操作紀錄記在 `job:<id>` 底下，不在對話裡；沿用派工當下那個對話的核准模式。
   核准面板出現在該工作的頁面；左側「工作」按鈕顯示有幾件在等你，視窗不在前景時發瀏覽器通知（每 3 秒查一次）。
   套用與還原仍然記在原本的對話下。
4. **可以停止。** 排隊中的工作直接移出佇列（不會開 worktree）；進行中的工作取消 OpenCode 這一輪並照常收尾。
5. **重啟不會自動再跑。** Rocky 重啟時，排隊中和進行中的工作都標成「已中斷」，不會自動開始或重做（遵守「結果不明的動作不自動重做」）。
   Rocky 關閉時會先停止進行中的工作。
6. **查詢工作。** 新的唯讀工具 `check_jobs` 列出這個對話派出的工作：狀態、改了哪些檔、Rocky 跑測試的結果；你問的時候 Rocky 才查。
7. 狀態多了「排隊中」：SQLite 不能改欄位的檢查條件，migration 4 重建 `jobs` 表；migration 期間先關閉外鍵、結束後檢查外鍵完整再打開。

## 還沒驗證的（限制）

- 同時只跑一個工作是固定的，還不能設定。
- （2026-10-06 補上，見下方「後續」。）工作完成時不會主動在對話裡通知（只有工作頁與左側標示、等你核准時的瀏覽器通知）。
- Windows 上的實際操作待擁有者確認。

## 後續：對話裡的工作卡片（2026-10-06）

- 派工的那個對話最後面有工作卡片：排隊第幾個、進行中、等你核准幾件；完成後顯示結果、改了幾個檔案、Rocky 自己跑的檢查有沒有過。
  卡片由 Rocky 從工作紀錄產生，不是模型寫的，所以不用再呼叫模型，也不會說出 Rocky 沒驗證過的事。
- 「套用到專案」打開該工作並直接列出套用計畫，確認方式和工作頁一樣（綁定內容雜湊）。「知道了」隱藏卡片（記在這台瀏覽器）。
  已套用、已捨棄的工作不再顯示。
- 視窗不在前景時，工作完成會發瀏覽器通知（Rocky 開著時看到的才通知，重新整理前已完成的不通知）。
- 新的 API：`GET /api/threads/:id/jobs`；`GET /api/jobs/summary` 多了最近 24 小時完成的工作。
