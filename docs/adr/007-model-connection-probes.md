# ADR-007: versioned model connections and bounded protocol probes

Status: implemented local slice; T-007 remains in progress.

The daemon owns connection configuration, server-side environment resolution and probing. Domain schema v3 adds model connections, save receipts and probe records under the existing single writer lock. Full replacement uses expectedRevision; request IDs bind to a canonical parsed intent hash. The public projection omits credential and CA reference names, returning availability flags. No raw secrets or provider response bodies are stored.

Use a per-connection Undici dispatcher (8.11.2 since 2026-10-04; ProxyAgent sets `proxyTunnel: true` so plain-HTTP endpoints still use CONNECT), never a global dispatcher or TLS override. The dependency already existed transitively and is now pinned directly. Test-only node-forge 1.4.0 generates ephemeral TLS certificates in memory without OpenSSL/Python or committed private keys. The pinned package declarations, [Undici ProxyAgent documentation](https://github.com/nodejs/undici/blob/main/docs/docs/api/ProxyAgent.md) and [Node TLS API](https://nodejs.org/api/tls.html#tlsgetcacertificatestype) inform the adapter; executed fixtures are the compatibility evidence.

The five-call capability probe is a fixed protocol diagnostic, not another model orchestration loop. It validates one exact nonce and a single known echo tool before supplying a synthetic tool result. It never accepts provider tool names as authority to dispatch application tools. Each send is counted durably before I/O, has no retry, and shares a 15-second cancellation deadline. In-flight probes are bounded to two per daemon and one per connection revision; repeated request IDs return the existing result. Shutdown waits for cancellation before closing the store.

Separate configuration, per-revision probe results and live runtime readiness. `/api/v1/capabilities` continues to report `runtimeAvailable: false` and `verified: false` for the model runtime while allowing `connectionProbing: true`. Existing Deep Agents fixture/evaluation execution is unchanged. Model-purpose routing, actual usage/currency budget enforcement and DNS/rebind coverage remain follow-up work. No P0 or global acceptance gate is closed by this slice.
