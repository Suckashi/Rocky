# ADR 0038：介面質感：深色主題跟隨系統、動態與對比原則

- 日期：2026-10-12
- 狀態：採用

## 背景

介面只有一套亮色、沒有 hover 與轉場回饋；窄視窗會把對話列表整個藏起來，找不到；送出鈕因為
`.icon-button.primary` 也吃到 `button.primary` 的左右 16px padding，箭頭被擠成一個點。

## 決定

- **顏色、陰影、動態全部是 `tokens.css` 的 token。** 亮色沿用 owner 設計稿的值；深色用
  `prefers-color-scheme: dark` 跟隨系統，不加設定開關。Roko 眼睛的琥珀色（`--accent`）只用在狀態光暈，
  不用在文字上。
- **對比至少 WCAG AA（4.5:1）。** 亮暗兩套的文字／底色組合都算過；為了過線，亮色 `--warn` 從
  `#c27a1a` 調深為 `#9e5e0d`，並新增 `--on-warn` 給警告底上的文字。
- **動態只做進場與狀態回饋**（訊息浮現、核准面板彈出、Roko 狀態光暈），都用 token 的時間與曲線；
  `prefers-reduced-motion: reduce` 時全部縮成 1ms。
- **窄視窗（≤720px）的對話／工作列表改成從側欄打開的抽屜**，Esc 或點旁邊關閉。
- 空白對話給三個開場建議，點了只填進輸入框，不會自動送出。程式碼區塊有複製鈕。設定頁在寬視窗有
  跟著捲動的目錄。
- **Roko 的視線跟著游標**：idle／揮手時用素材裡 16 個方向的注視影格轉向滑鼠或觸控筆（觸控不觸發），
  停 2.5 秒回到原本動畫；工作中、等待、失敗的狀態動畫不會被打斷。
- 核准選項改成一般清單裡的按鈕（焦點本來就在按鈕上，`listbox/option` 角色不正確）；工具卡從
  `<details>` 改成有 `aria-expanded` 的切換按鈕，「預覽」不再包在 `<summary>` 裡。
- 全域快捷鍵：`Ctrl/⌘+Shift+O` 開新對話，在欄位外按 `/` 回到輸入框（以 `aria-keyshortcuts` 標示）。
- 伺服器對 `/assets/*`（Vite 以內容雜湊命名）回 `Cache-Control: public, max-age=31536000, immutable`；
  `/assets/` 下找不到的檔案回 404，不再退回 index.html，以免頁面被當成腳本永久快取。
- 網頁建置把 `streamdown` 換成 `src/web/vendor/streamdown.tsx`：CopilotKit 只在它自己的聊天元件
  （Rocky 沒用）引用它，真品會把 KaTeX、parse5 帶進主程式。主程式 2,205 KB → 1,614 KB。
- 伺服器對網頁檔 gzip（`hono/compress`，只掛在 `/api` 之後的網頁路由，聊天串流不受影響）；
  `/roko/*`、`/rocky/*` 快取一天；`/assets`、`/roko`、`/rocky` 下找不到的檔案一律 404。
- **Roko 的圖改為每列一個無損 WebP**（`assets/roko/rows/`，owner 於 2026-10-13 同意）：每個像素都和原始
  PNG 相同；原始 PNG 留在 repo 當來源紀錄。第一個畫面只等它要顯示的那一列（揮手列 113 KB，整張 PNG
  3 MB），index.html 預先載入揮手與待命兩列，其餘在瀏覽器閒置時補齊。
- `src/web/zod-config.ts` 在所有依賴之前設定 zod `jitless`：CSP 本來就禁止 eval，zod 的快速路徑從來跑不了；
  先講清楚就不會再用 `Function('')` 試探而在瀏覽器留下 CSP 違規紀錄。
- **配色改為 Roko 的暖石色與琥珀色**（owner 於 2026-10-13 同意，取代設計稿的藍紫主色）：琥珀底配深色字，
  使用者訊息用 Roko 面罩的深墨色；文字對比全部 ≥ 4.5:1，欄位外框 ≥ 3:1（`--input-border`）。
- **移除右側 Roko 面板**（owner 同意）：全身的 Roko 坐在輸入框（或取代它的核准面板）上緣，姿勢與旁邊的狀態標籤
  說明它在做什麼（owner 選的「上台」）；專案與模型變成輸入框工具列的標籤；
  每個畫面只出現一個大 Roko。
- **執行動作的角色統一叫 Roko**（owner 決定）：Roko 提出、詢問、記住、驗證；Rocky 是產品名（啟動、隱私、網路）。
- Roko 的視線：往左看的角度用往右看的影格水平翻轉（CSS `rotate: y 180deg`），讓四個方向的姿勢一致；
  原圖沒有修改。
- Roko 會跟著讀：在輸入框打字時，待命或揮手的 Roko 轉頭看向游標所在的字（用文字寬度估算位置，沿用視線影格），
  停下來一會兒就回到原本的動作。
- 回合的變更卡在串流途中會移到新位置、被重新掛載；卡片的狀態（展開、已載入的變更、訊息、復原資訊）
  依「對話＋回合」記在模組層級，打開的 diff 不會在使用者眼前收起來（這也是 e2e 偶發逾時的原因之一）。
- 小尺寸的 Roko 改用圓形臉部頭像，裁切點依 `assets/roko/roko-faces.json`（從原圖量出每格面罩中心）跟著影格移動。
- 1100px 以下對話列表收進抽屜；600px 以下側欄變成頂部列；停用按鈕亮暗共用中性樣式。
- **有風險的核准不預選**（owner 決定）：受保護檔案、危險指令、機密檔、對外動作時，沒有預先選取的選項，
  單按 Enter 不會核准；其他情況仍預選「允許一次」。
- **設定頁留在 App 框架內**（owner 決定）：左側導覽保留；寬視窗每個區塊是「名稱｜控制項」兩欄。
- **主題設定**（owner 決定）：跟隨系統／淺色／深色，存在設定裡（`PUT /api/settings/theme`），並在瀏覽器保存一份，
  下次開啟在畫面出現前就套用。
- **單一檔案還原與復原**（owner 決定）：還原 API 加上 `partial`（只還原指定檔案；「全部還原」仍要求整個計畫
  相符）與 `target: 'after'`（把檔案寫回這輪改完的樣子，用來復原）。成功的還原會回傳復原所需的內容雜湊；
  每次寫入都經過 gate 並留操作紀錄。復原按鈕不會自動消失（WCAG 2.2.1），保留到下一次還原。
- **首次設定只有一個主要動作**（owner 決定）：「開始和 Roko 對話」會先儲存模型設定再進入對話，模型表單在這頁
  不另外顯示「儲存」；設定頁的模型表單照舊有自己的儲存鈕。
- **空白畫面各有自己的姿勢**（owner 決定，只用現有影格、不改原圖）：首次設定揮手、新對話待命並看著游標、
  沒有背景工作時休息（原圖的 review 列，眼睛半閉）、鎖定頁等待。
- **一次修改只出現一次**（owner 決定）：寫入成功、而且這輪的變更卡會列出的檔案，不再另外顯示工具卡；變更卡
  收起時列出改了哪些檔案，文件和圖片可以直接從這裡在側邊預覽。文件的「在側邊看排版後的樣子」放在 diff 下方。
- **核准面板的權重**（owner 決定）：沒有風險時，「允許一次」是實心琥珀色的一列，看得出是預期的答案；有風險時
  （受保護、危險、機密、對外）維持不預選、各選項等重。拒絕平常是中性文字，滑過或選到才變紅。說明裡的路徑
  顯示成專案內的相對路徑，完整路徑在滑鼠提示。
- **新對話的空白畫面**（owner 決定）：Roko 放大並站在一圈暖光裡；標題下說明 Roko 會在哪個資料夾工作，還沒選
  資料夾時這行是前往設定的連結。
- **短對話貼著輸入框**（owner 決定）：訊息從輸入框往上長，最後一則訊息緊鄰 Roko 和輸入框，空白在上方。
- 不使用網路字型（維持 `tokens.css` 原本的做法），只在字型清單前面加上 Windows 的 Segoe UI Variable。

## 驗證（雲端 Linux，Node 22.22.0，Playwright 的 Chromium）

- `npm run check`：通過（30 個測試檔，331 通過、5 略過）。

  改版後通過，無法確定是改版修好還是時序偶發。變更卡記住狀態之前連跑 5 次有 1 次失敗（「對話途中重新整理」
  那一步等不到回覆）；之後連跑 6 次都是 39 項通過。那一次失敗的根因沒有找到，6 次通過不代表已經排除。貼底排之後又出現一次同一步的失敗（等不到回覆）。
