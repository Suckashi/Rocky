# MCP resource and prompt metadata discovery

2026-10-03. Source `f9e9a22a101f8b3443619aac2fd996cf6150239a`; Windows x64, Node 24.12.0/npm 11.6.4. T-015/T-016 remain in_progress. Previous turn made authoritative implementation/test progress; this continuation adds data discovery without closing full MCP acceptance.

The existing mcp_discover strategy now accepts kind=tools/resources/prompts (tools remains the default). Resource entries and URI templates share a tagged, five-entry page; prompt entries expose metadata only. ServerId and registryRevision remain required when selecting a server. Descriptions and arguments remain untrusted data, never system policy or authority. Neither resource URIs, template expansion, resource links nor prompt messages are fetched or applied.

The daemon uses public APIs from the pinned MCP SDK to list resources, resource templates and prompts on demand. Catalogs belong to the active connection, with copied return values and no second polling/storage source. Unsupported capabilities return empty lists. Pure resource/prompt servers no longer receive an unconditional tools/list request during startup. Resource/prompt list-change notifications close the old connection; explicit reconnect increments registryRevision, invalidating stale discoveries and the existing tool preparation boundary.

Discovery has an aggregate 1000-entry/2 MiB limit, at most 100 pages per list, duplicate identity/cursor checks, a whole-discovery abort deadline using configured toolTimeoutMs and a credential rejection boundary. Stop, config change and caller abort invalidate/cancel active discovery. Model delivery also uses the existing MCP/model redactors. URI strings are metadata only and cannot expand network policy. A connected server is not proof that its descriptions are trusted or that any Work/effect has succeeded.
