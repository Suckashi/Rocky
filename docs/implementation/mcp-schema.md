# Configured MCP schema boundary

2026-10-03. Source commit `4112fb78dc9a085111aa8ee0b803c5b1f96e3046`; Windows x64, Node 24.12.0 / npm 11.6.4, local fixture mode. T-016 remains **in_progress**.

`apps/daemon/src/mcp-schema.ts` validates original JSON Schema, with pinned Ajv 8.20.0 / ajv-formats 3.0.1. The official MCP client receives the same provider for structured output validation. Discovery checks every input/output schema before publishing a ready registry. No flattening into a string-only schema, defaults, coercion, property removal or schema fetches. Missing draft uses 2020-12; explicit draft-07 is also supported. Every schema gets a fresh compiler so duplicate upstream `$id` values cannot reuse another server's validator.

Input/tool metadata use the existing canonical JSON boundary (64 KiB, depth 64, 10,000 JSON nodes). Schema traversal additionally limits reference expansion to 10,000 visits and rejects cycles. Ajv compiles references separately and uses fast format validators. This is not a proven hard CPU deadline: isolated compilation/validation and adversarial worst-case performance remain pending.

Currently unsupported schemas fail closed: arbitrary `pattern` / `patternProperties`, external or named-anchor references, recursive/dynamic references, unknown drafts/formats/keywords. Local nonrecursive JSON-pointer refs are supported. These restrictions can prevent legitimate integrations from connecting; they are a recorded compatibility gap, not completed full-schema acceptance. Regex/recursive support needs bounded isolation before enabling it.

`McpManager.prepareTool` rechecks active connection, configuration and registry revision, finds the exact upstream tool, validates arguments, and returns a copied raw descriptor plus identity. It never calls a tool or creates an operation. Identity contains server/config/registry revision, original name, a stable per-server/name runtime alias, and a hash of complete raw metadata. Annotation changes affect the hash; even `readOnlyHint: true` remains `effect: unknown` and grants no authority. Config/registry revision and the eventual operation intent must remain part of the approval fingerprint; schema hash alone is insufficient.

Tests cover nested refs/arrays/enums/limits/additional properties, no coercion/mutation, duplicate `$id`, date-time formats, unsafe schemas, same-name namespaces, metadata changes, actual stdio and Streamable HTTP discovery, invalid parameters, missing tools, stale revisions, Stop revocation, and failure of unsafe input/output discovery. Fixtures are synthetic MCP servers, not business-system/live-provider evidence.

Evidence: [verification](evidence/2026-10-03/mcp-schema/verification.json). `check`, `lint`, `build` and 25 focused tests passed. Build retains the existing bundle-size warning. An initial duplicate-ID test used an invalid URN (`urn:duplicate`); corrected to `urn:rocky:duplicate`, then reran the checks. No UI changed; browser checks and full regression were not rerun in this slice.
