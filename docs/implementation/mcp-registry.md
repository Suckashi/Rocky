# Rocky MCP configuration registry

Source c9d8d4e; T-014/T-021 contribution. The daemon stores one application-owned MCP configuration in SQLite domain schema14. Initial mcpServers is empty; each server defaults disabled. The JSON shape follows the main spec's mcpServers plus x-rocky version1. Stdio command/args/cwd/env and HTTP url are mutually exclusive, with exactly matching transport metadata. Foreign extensions, unknown fields, inconsistent identities, oversized configuration and credential-shaped literal env/CLI flags are rejected. There is no foreign config importer or service migration.

GET/POST `/api/v1/mcp-config` expose read/save; mutation requires the existing local owner session. Save is a full atomic replacement with expectedRevision, canonical hash and stable requestId. Configuration plus receipt commit together. Validation, stale revision, changed request content or injected receipt failure leave the prior configuration intact. A duplicate request returns its original receipt even after later updates/restart. Reads verify the stored hash; corrupt data is not silently reset to empty.

Environment credential references are resolved only by the daemon's launchSpec seam. Stdio environment is constructed from explicit allowlist, nonsecret literals and destination-variable references, without shell expansion. Default cwd is Rocky's data-root/connections/mcp; relative cwd/executable paths resolve there. Relative command arguments are literal arguments interpreted by the executable under that configured cwd. Bare executable names resolve through the configured launch PATH. This seam has not yet been connected to SDK process creation, so no inherited-environment/process isolation claim is made. Configured servers are third-party processes, not an OS sandbox.

HTTP headers use references only, with a single Authorization reference and client-owned protocol/session headers denied. Bearer refs do not put actual tokens in saved JSON. Missing refs fail unavailable, disabled servers cannot produce a launch spec and stale config revisions fail409. Known referenced credential strings cannot be saved as literal configuration values. Public Work/evidence and ordinary HTTP output use combined model/MCP redaction, retaining observed retired MCP secrets in memory until daemon close. Successful MCP config responses deliberately preserve validated reference mappings; generic key redaction would corrupt a reference named Authorization. They never expose resolved launchSpec/env/header values. Unknown secret values hidden in arbitrary executable arguments cannot be recognized universally; do not put plaintext credentials in configuration.

UI adds an advanced JSON editor within the existing OpenDots-aligned settings dialog. It reports disabled or configured-but-not-connected, explains that saving starts nothing, validates before submission and keeps a stable UUID for ambiguous retry. No fake ready/verified state, new polling loop, Intelligence or managed connector settings. Four widths checked; the old global composer textarea layout is now scoped so config/steering editors own their layout.

Tests prove empty/default/strict schemas, CAS/idempotency/restart, transaction rollback, exact environment/path construction, unavailable/disabled behavior, plaintext rejection and retired-secret redaction. API tests prove owner-session mutation and preservation after rejected foreign input. Browser tests save/reload, reject foreign extensions, focus Save and check horizontal overflow at1440x900,1280x800,390x844,320x844.
