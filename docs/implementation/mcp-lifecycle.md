# Configured MCP lifecycle and discovery

Sources5488911/4b2384c; T-015/T-021 contribution. Daemon-owned official SDK clients manage configured stdio and Streamable HTTP connections. Local owner-session connect/stop commands carry requestId and exact config revision. Persisted lifecycle command IDs prevent replay after Stop/restart; responses show current connection state. There is no automatic reconnect or tool-call retry. Config changes synchronously invalidate access, abort and close old connections. Daemon restart resets stored active states to configured and marks pending commands interrupted; explicit reconnect is required.

States distinguish disabled/configured/starting/ready/failed/stopping. Ready means completed protocol initialization and bounded full tool discovery, not tool execution or Work success. Catalog identities include server/config/registry revisions. Repeated cursors, duplicate tool names and excess discovery fail closed; tool-list-changed notifications close the connection and require explicit refresh so stale catalogs cannot be used. Limit:100 pages,1000 tools,2MiB discovery,2MiB stdio buffer/HTTP response. Registry increments only after complete discovery. Catalog is private and inaccessible unless that exact live connection/revision is ready.

SDK stdio defaults would inherit additional environment values. Unapproved defaults are explicitly emptied, configured env is injected and Windows names are normalized with case-insensitive reference lookup. Bare executable resolution and cwd follow the registry contract. SDK closes the direct child; real Node fixture PID disappearance and cancellation during discovery are tested. This is not an OS sandbox or proof of arbitrary descendant-tree cleanup.

Stderr is limited to64KiB total and16 diagnostic fragments of8192 chars. UTF-8 decoding and credential-aware streaming redaction handle split chunks; shutdown drains stderr without publishing stale state, masks incomplete credential prefixes at EOF and persists only sanitized diagnostics. Untrusted protocol error text is not echoed. Known credential-bearing discovery is rejected. HTTP fetch is bound to the exact configured endpoint and exact active connection instance, denies redirects/credential forwarding, bounds response bytes and aborts with revoked state. Reconnection retries are disabled. Interactive OAuth currently reports unsupported rather than attempting managed services; DNS/proxy/CA/credential-version policies remain incomplete.

GET `/api/v1/mcp-servers` returns state; POST `/mcp-servers/:id/connect` and `/stop` mutate through the existing owner-session guard. Settings maps real states/counts/timestamps to existing neutral cards, provides Connect/Stop/Refresh and collapsed diagnostics, preserves config editor and explains that conversation routing remains unavailable. No separate polling/event source or fake tool outcome. The stale saved-but-not-connected hint is cleared when a connection is requested.

Windows fixture evidence: actual Node/HTTP SDK initialization, tool discovery/stop; direct child PID cleanup; paged metadata, cursor-loop denial, stderr quota/redaction, startup cancellation, stale/duplicate commands, config revocation and redirect isolation.
