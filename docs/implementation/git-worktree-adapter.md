# Local Git worktree adapter foundation

2026-10-04, Windows x64, Node24.12.0/npm11.6.4/Git2.52.0.windows.1. Source d1181200442a8e9fa4d3b2686dc8a8bfecaf5abf. This adapter is implemented and tested, but not yet exposed in production: no native worktree tool, API, UI, exact consent/operation-ledger integration or automatic background coding routing exists. T-017 remains in_progress.

GitWorktree prepares a canonical main Git root, new sibling destination and application-shaped codex/rocky UUID branch. Installed Git is resolved from absolute PATH entries outside the project cwd; arbitrary executable/shell interpolation is not accepted. Prepared context includes committed HEAD, root/Git-directory identity, bounded config fingerprint and canonical destination snapshot. Creation revalidates before dispatch. A new worktree starts from committed HEAD and deliberately does not copy dirty/untracked source contents; source files/branch are preserved in the tested cases. The source Git database does gain the new branch/worktree registration.

Commands use explicit argv, cleared credential environment, no terminal prompt, no allowed transport protocol, disabled hooks/fsmonitor/submodule recursion and no inherited global/system Git config. Repository include config is read for exact fingerprint/filter detection; filters are rejected rather than running their code. Existing source worktree/nested root/empty-repo/non-Git cases are not presented as supported. No reset/clean/force/deletion or automatic rollback occurs. After dispatch, errors classify worktree_unknown because Git may already have created a branch or metadata. Caller must persist unknown and retain scope; this adapter does not itself authorize or journal an effect.
