# Typed MCP evidence and explicit model image input

2026-10-03. Source `0cf5d5fbd5d886f098d83229c3ba7fe71bbde21c`; Windows x64, Node 24.12.0, npm 11.6.4. T-007/T-011/T-016/T-019 remain in_progress. Goal stays active.

The daemon validates SDK CallToolResult and supplies a typed delivery envelope through existing worker IPC. Native mcp_call returns content_and_artifact: original structured types and source revisions remain in the sanitized checkpoint artifact; text, embedded text resources, structured data and unfetched resource links are explicitly untrusted model evidence. Private operation results retain original server receipts. Known credentials and secret-shaped fields are redacted before graph/model delivery. A protocol result alone does not prove a remote job finished.

PNG/JPEG inline images have canonical base64, size, signature and dimension checks (1 MiB, maximum 4096 per dimension). These are bounded header checks, not a complete decoder/CRC guarantee. Unsupported media is retained as uninspected evidence. Resource links are not fetched. No fake image or tool output enters the normal product; visual_sample exists only in an explicitly enabled loopback test fixture.

Model configuration defaults visionEnabled to false. The reference-aligned settings form exposes an explicit opt-in, independently of proxy/CA controls, and labels support as unverified. The daemon forwards capability metadata through its owned worker start message without forwarding credentials. Disabled mode forwards a not-inspected marker instead of binary image input. Anthropic uses nested image blocks in tool_result; OpenAI-compatible requests preserve tool text and use a separate user image bridge labelled as untrusted tool evidence. Image configuration does not create a passed connection/vision probe.

Installed Deep Agents 1.14.1 FilesystemMiddleware stringifies large mixed tool results. RockyMcpEvidence uses its public, shared filesystem state schema to retain native offload while replacing the same ToolMessage identity with a text pointer and typed images. The model-readable native scratch file retains text/structured evidence, not image base64. No second runtime, storage or polling source is introduced. Tests inspect the actual SQLite graph checkpoint, provider payload and private daemon ledger across both providers, both image settings, small and large results.
