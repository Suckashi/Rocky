# Rocky 核准設計（V1）

> 狀態：已定案，2026-10-05。手感參考 Kimi Code（MoonshotAI/kimi-code @ 21406fb），
> 再補上 Rocky 的安全底線：核准綁定內容雜湊、操作紀錄、結果不明不重做。

## 使用者看到的：三種模式

每個 session 一個模式，隨時可以切換（輸入框旁的模式選單，或 `/mode`）。

| 模式 | 行為 |
|---|---|
| 每次問 | 改檔和指令都先問；讀取不問 |
| **需要時才問（預設）** | 改檔、一般指令都直接做；只有危險指令、機密檔、對外動作會問 |
| 放手 | 除了兩條底線，其他都不問 |

**兩條底線不受模式影響**：危險指令一定問；對外動作一定問。

- 對外動作：MCP 工具（標成唯讀的除外，而且這個標記不能用來放寬寫入）、網路寫入、專案資料夾以外的檔案、刪除工作開始前就存在的檔案。
- 這兩條是 Rocky 和 Kimi 最大的不同：Kimi 的「從不問」連危險指令也會放行。

## 判斷順序（由上往下，第一個有結論的就生效）

1. 使用者設定的**禁止**規則 → 拒絕
2. **危險指令偵測** → 問
   - 用語法樹分析，不比對字串；拆開 `sudo`、`env`、`sh -c`、`cmd /c`、`powershell -Command` 等包裝，最多拆 4 層。
   - Windows 涵蓋 `format`、`diskpart`、`bcdedit`、`Remove-Item -Recurse -Force`、`Stop-Computer` 等。
   - 無法解析的指令：「每次問」模式會問，另外兩種模式交給後面的規則判斷。
3. **機密檔、受保護路徑** → 讀取機密檔直接拒絕；寫入受保護路徑要問
   - 機密檔：`.env*`、SSH 金鑰、憑證檔。受保護路徑：`.git/`、`AGENTS.md`、各種設定檔等。
   - shell 指令的參數也會檢查路徑。
4. **對外動作** → 問
5. **本 session 已核准過**（只限完全相同的雜湊）→ 允許
6. 使用者設定的**允許**規則 → 允許
7. **依模式決定**
   - 「每次問」：讀取允許，其他都問。
   - 「需要時才問」：讀取、專案內改檔、一般指令都允許。
   - 「放手」：全部允許。

**內建安全清單**：讀取 `package.json` 的 test、lint、typecheck、build 腳本，再加上 `git status`、`git diff`、`git log` 等唯讀指令。在「每次問」模式下，這些也直接執行。

## 改檔：先存快照，事後再看

- 每次寫檔前，先把原內容存成快照（依內容雜湊存放）；不是 git 專案也可以還原。
- 每輪結束時顯示一張卡片：「這輪改了 N 個檔案　[看看]　[全部還原]」。

## 核准面板

- **直接取代輸入框**，不跳出視窗。
- 第一行用人話說明要做什麼，並標出是誰提出的（Rocky、OpenCode、子 agent）。
- 指令顯示完整參數陣列與執行資料夾；改檔顯示 diff。按 `Ctrl+E` 看全螢幕預覽。
- 選項：`1` 允許一次、`2` 這個 session 都允許、`3` 拒絕、`4` 拒絕並說明（在同一行輸入原因）。
- `Enter` 選擇目前項目，`Esc` 拒絕。
- 視窗不在前景時，發瀏覽器通知；Roko 換成「等你核准」的動畫。
- 有好幾件事等你決定時，依序排隊，面板上顯示「還有 N 件」。

## 規則與記憶

- **「這個 session 都允許」**：只放行完全相同的內容，也就是雜湊一樣。
  - 指令：參數陣列 + 執行資料夾。
  - 檔案：路徑 + 操作種類。
  - MCP：伺服器 + 工具 + 參數。
  - 不比對說明文字。Kimi 只比對指令的前 50 個字，所以會一起放行前 50 字相同、後面不同的指令。
- **永久規則**：用參數前綴比對，例如 `npm test *`。只能由你在設定頁新增，或接受 Roko 的建議。規則一定看得到，也能撤銷。
- **外部 agent**：Rocky 只回 `allow_once` 或 `reject_once`。「這個 session 都允許」記錄在 Rocky 這邊，不交給外部 agent。

## 拒絕之後

- 這一輪繼續，不會讓整個工作失敗。
- 工具結果會告訴模型：「使用者拒絕了，原因：…。不要用同樣的方式重試，換個做法。」

## Plan 審查

- 模型最多提出 3 個方案，你可以選一個、要求修改，或拒絕。
- 核准後，計畫裡列出的指令視為已核准，但只限完全相同的指令。

## 操作紀錄與結果不明

- 每個動作執行前，先寫一筆「意圖」操作紀錄；執行後再寫結果：成功、失敗或不明。
- 結果不明時，用人話說明，例如「不確定剛剛有沒有成功（MCP 沒回應）」，並提供兩個按鈕：
  - 「我看過了，成功了」
  - 「沒成功，再做一次」：這會當成一個新動作，重新走一次核准。
- 永遠不會自動重做。

## 刻意不照抄 Kimi 的地方

- 核准綁定內容雜湊；Kimi 只綁定一個隨機 id。
- 「這個 session 都允許」不比對說明文字，也不會一次放行整個 MCP 工具。
- 抓網頁和派子 agent 不在預設放行清單裡；抓網頁在「每次問」模式下要問。
- 有操作紀錄，也有「不明」這個結果狀態。
- 面板會標出是誰提出的。
